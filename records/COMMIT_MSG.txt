R3 gate: 3UTR-RBP root cause found and fixed; additive LR remedies implemented

A 3-mer logistic regression reaches 0.781 ACC on the official 3UTR-RBP split, so the
task is learnable and the pipeline was at fault. Controls isolate the knob: fp32
reproduces the identical degenerate 0.6675, so it is not an fp16/ALiBi artefact; a
frozen encoder reaches 0.7796, so the pre-trained features are fine; full fine-tuning
at lr 1e-4 destroys them within about 100 steps, after which train loss rises from
0.549 back to 0.64 and the head latches onto the class prior. Both remedies beat the
published numbers: lr 2e-5 gives ACC 0.8250 / F1pos 0.7381 and discriminative LR
(encoder 1e-5, head 1e-4) gives 0.8132 / 0.7076, against the published 0.786 / 0.751.

- src/rnajepa/finetune.py: --freeze_encoder and --encoder_lr_scale, the latter
  building its own parameter groups and cosine schedule.
- configs/tasks.yaml v2: per-task learning rate plus an lr_status field marking which
  values are verified and which are still to be selected by a dev sweep.
- records/INVESTIGATION_rbp_0_degenerate.md: the full control table.
- scripts/pretrain_pipeline.sh: unattended corpus verification, preprocessing, alpha
  smoke sweep and V1/V2 launch, idempotent at every stage.
