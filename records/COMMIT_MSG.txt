Contract verifier, and a factor-probe fix found by using it

scripts/verify_contract.py reduces every requirement in the project spec to a check
that reads real state -- files, md5s, row counts, ledger rows, result.json contents --
and reports PASS / FAIL / PENDING with the evidence. A stage that has not produced its
evidence is reported as not done, which is the point: the first run reports 10 PASS,
7 FAIL, 6 PENDING, and every FAIL is an artefact that legitimately does not exist yet
(V1/V2 checkpoints, ablation arms, the full-corpus region sidecar, candidate
evaluations). It also surfaces the two gate tasks whose reproduction is still outside
tolerance and the one task whose download is incomplete.

The verifier immediately caught a real bug of mine: eval/factor_probe.py failed after
the earlier refactor because the write section still referenced `coords`, which had
moved into a per-pool scope, so it wrote a zero-byte factor_probe.json. The write
section now emits one coordinate file per pool and reports per-pool sizes and the
protocol note inline, so the region pool can never be quoted as evidence for C3 by
mistake.

Environment: the dedicated mrnabert env finished installing (torch 2.1.2+cu121,
transformers 4.32.0 and accelerate 0.24.1 exactly as the official requirements pin,
einops, sklearn, scipy, pandas, peft). Triton was then uninstalled, which is the
official README's instruction and selects the pure-PyTorch attention path -- so all
models in this study share one attention implementation, and anyone following the
README reproduces it.
