Ablation arms, a pure-MLM baseline path, and the learning-curve probe

- model.py: jepa_target gains "none" (pure MLM -- teacher, predictor and every
  regulariser are skipped, so A0 measures MLM-only at the same step and data budget
  rather than paying for a latent branch it does not use) and "cls" (global objective
  only, which with n_factors=1 is the single-vector JEPA-DNA minimal arm A1).
  Verified on GPU: the A0 run reports loss == loss_mlm and jepa/var/cov/orth exactly 0.
- scripts/pretrain_ablations.sh: the eight A0-A5 runs, each differing from the main run
  in exactly one factor, launched sequentially with a capacity wait. Sequential on
  purpose: launching them together is how batch sizes ended up halved earlier, which
  would confound the ablation with a protocol change.
- scripts/queue_matrix.py: refuses to enqueue a matrix whose model_path does not exist
  yet. Without it, queueing V1/V2 evaluation before the runs finish launches every cell
  against a missing checkpoint, burning GPU slots and filling the ledger with noise.
- eval/linear_probe_curve.py: Fig.6c. Frozen-feature probe over a list of pre-training
  checkpoints, using mean-pooled last-layer states because that is the feature-
  extraction recipe the released README documents -- the probe should not quietly use a
  different representation from the baseline.
