# 评价口径用户决策：无监督预训练暴露不作为排名否决项

日期：2026-11-29  
状态：用户已确认，作为当前项目统一评价口径。

## 1. 用户决策

RiNALMo 等 backbone 的无监督预训练阶段见过评价序列，**不再作为主线阻塞、排名否决或 clean-OOD gating 的理由**。

后续测评原则：

1. 做好下游训练/评价去重；
2. 保证标签协议一致，避免循环标签；
3. 保证覆盖率完整，缺预测不补 0；
4. 同序列、同标签、同覆盖、同指标下正常排序；
5. 不把精力继续消耗在“无监督预训练见过所以不能排名”的扩展审计上。

## 2. 保留与废止

### 保留

- 下游 train/dev/test 精确/同源去重；
- 标签来源与循环标签修复；
- projected-reference 与 official-reference 分栏；
- 覆盖率完整性检查；
- 历史预训练暴露审计 artifact，作为可追溯记录。

### 废止当前 gating 用途

- 不再因 RiNALMo 预训练 EXACT/HOMOLOGY 暴露而否决 benchmark 排名；
- 不再把预训练暴露未知作为主线正结果阻塞；
- 不再要求完整官方预训练 manifest 闭合后才允许正常排序；
- 不再把 `NOT_DETECTED_UNKNOWN/UNCHECKED` 的预训练层写成 SOTA 否决门。

## 3. 论文表述口径

可以写：

- 使用下游去重后的标准 benchmark；
- 使用官方参考标签或明确声明的 projected-reference 协议；
- 同覆盖、同指标正常比较；
- 历史预训练暴露审计可作为补充说明，但不是排名资格门。

避免写：

- 因无监督预训练见过序列而否定整个 benchmark；
- 把预训练暴露审计当作主线失败原因；
- 用预训练未知阻止正常结果发布。

## 4. 对当前主线的影响

- structured margin 四臂继续按结构终点和对照门裁决；
- 若结构门通过，可进入正常 benchmark 排序与外部比较；
- 数据问题重点收敛为：循环标签、协议混用、覆盖不足、下游泄漏；
- 不再新增围绕无监督预训练暴露的 blocking 实验。

## 5. 版本化原则

本决策不删除历史审计，不修改旧 artifact 数值。所有旧文档中“预训练暴露导致不能排名”的表述，应更新为历史审计/旧政策；当前政策以本文档为准。
